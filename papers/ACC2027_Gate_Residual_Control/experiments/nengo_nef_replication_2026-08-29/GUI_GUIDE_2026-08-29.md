# Nengo CMG--PES MuJoCo GUI operator guide

## Purpose and scientific status

The GUI is an interactive, transparent view of the validated controller. It is
not a replacement for the frozen 45 s batch campaign and its paper metrics. Two
synchronized MuJoCo plants run in one Nengo graph:

1. **PD twin:** quaternion PD, actuator mixer and rotor-limited MuJoCo plant.
2. **CMG--PES twin:** the identical baseline plus six paired coupled
   membrane--gate units, a Nengo PES-adapted decoder and bounded residual torque.

Platform, mission, duration and actuator scale are fixed at launch so both
branches remain matched. The GUI adds a 1 microsecond low-pass connection on
each plant torque input to break the closed-loop algebraic cycle required by
Nengo's scheduler. At the 0.5 ms simulation step this is a negligible GUI-only
scheduling adaptation; the batch runner remains canonical for numerical claims.

## Launch

```powershell
$py = 'C:\Research\papers\ACC2027_Gate_Residual_Control\.venv\Scripts\python.exe'
$root = 'C:\Research\papers\ACC2027_Gate_Residual_Control\experiments\nengo_nef_replication_2026-08-29'

# Skydio X2, hard45
& $py "$root\launch_gui.py" --platform x2 --mission hard45

# Crazyflie rotor-design variant, yaw360
& $py "$root\launch_gui.py" --platform cf2-rotor --mission yaw360

# Recommended live 3D demonstration: Nengo dashboard + neural MuJoCo twin
& $py "$root\launch_gui.py" `
  --platform x2 --mission hard45 `
  --mujoco-viewer neural --realtime --viewer-fps 30
```

Supported missions are `hover`, `roll`, `full3`, `hard45`, `hardstep`, and
`yaw360`. The launcher defaults to actuator scale 1.0 for X2 and the explicitly
declared 1.5 rotor-authority design variant for CF2. Override only for a named
sensitivity test, for example `--actuator-scale 1.25`.

The launcher uses the custom backend in `nengo_dt0005_backend.py`, ensuring the
same 0.5 ms neural/control step used by the batch campaign. It also avoids the
Windows console-entry-point permission problem seen with `nengo.exe`.

## Live MuJoCo viewer

`--mujoco-viewer neural` opens a passive native MuJoCo window attached directly
to the CMG--PES plant. `--mujoco-viewer baseline` instead shows the matched PD
plant. Both twins continue running in the same Nengo simulation regardless of
which one is visualized; the Nengo dashboard remains the simultaneous
comparison surface.

Use `--realtime` with the viewer. It makes Nengo simulation time follow the
wall clock without changing the fixed 2 kHz controller/physics step. Viewer
updates are throttled independently by `--viewer-fps` (30 Hz by default), so
rendering does not become a 2 kHz control-loop operation. Closing the native
viewer does not terminate the simulation; stop the full session with `Ctrl+C`
in PowerShell.

For numerical campaigns, omit both flags. The default remains headless and
unpaced so reproducibility and throughput are unchanged.

## Dashboard map

| Panel/control | Channels | Interpretation |
|---|---|---|
| Quaternion-angle error | PD, CMG--PES | Direct live tracking comparison in radians. |
| Attitude tracking | PD r/p/y, CMG r/p/y, reference r/p/y | Verifies all three attitude DOFs and cross-axis excursions. |
| Normalized torque | baseline PD, residual, final command for x/y/z | Shows what the residual changes and whether total torque approaches the modeled limits. |
| Paired currents | `J+x,J+y,J+z,J-x,J-y,J-z` | Signed PD effort encoded as six nonnegative unit currents. |
| Membrane voltage | `v+x...v-z` | Continuous internal membrane state of every CMG unit. |
| Gate | `r+x...r-z` | Continuous gate state of every CMG unit. |
| Decoder activity | `a+x...a-z` | Activity supplied to the learned decoder; it depends jointly on membrane and gate dynamics. |
| Decoder norms | `||W_x||,||W_y||,||W_z||` | Online PES evolution for each residual-torque output axis. |
| Rotor comparison | PD motors 1--4, CMG motors 1--4 | Normalized motor commands from both twins, including allocation and saturation effects. |
| Residual authority | `beta` in [0, 0.75] | Multiplies the normalized decoded residual before torque limiting; paper setting is 0.5. |
| PES learning enable | 0 or 1 | Multiplies the PES error. Use exactly 0 for frozen decoder and 1 for adaptation. |

The neural signal sequence is

\[
q_d,q,\omega \rightarrow e_q,\tau_{PD}
\rightarrow J_{\pm x,\pm y,\pm z}
\rightarrow (v_i,r_i,a_i)
\rightarrow y=W a
\rightarrow \delta\tau=\beta\,\tau_{\max}\odot\operatorname{clip}(y,-1,1),
\]

followed by

\[
\tau=\operatorname{clip}(\tau_{PD}+\delta\tau,-\tau_{\max},\tau_{\max}).
\]

The decoder learns from the signed target `y* = clip(-8 e_q,-1,1)` through
Nengo's PES rule. The GUI learning switch multiplies `e_PES = y-y*`; it does
not bypass the CMG state dynamics or the residual path.

## Fair operating procedure

1. Launch the desired platform/mission and leave `beta=0.5`, learning `=1` for
   the reproduced adaptive case.
2. Press play and inspect error, attitude, torque, neuron states, decoder norms,
   and motors together.
3. For a PD-only view, set `beta=0`; the left PD twin is always the authoritative
   simultaneous baseline.
4. For a fixed-decoder view, reset the simulation first, set learning to `0`,
   and then press play. Merely switching learning off after a run freezes the
   already-adapted weights and is not a clean fixed-decoder comparison.
5. Relaunch when changing platform or mission. Do not compare traces obtained
   with different mission duration or actuator scale as if they were matched.
6. Use `run_campaign.py` and `compile_and_plot.py` for all reported numbers and
   archived figures.

## Verification

```powershell
& $py -m py_compile `
  "$root\gui_cmg_pes_mujoco.py" `
  "$root\launch_gui.py" `
  "$root\nengo_dt0005_backend.py" `
  "$root\smoke_test_gui.py"

& $py "$root\smoke_test_gui.py"
```

The smoke test builds and advances both X2/hard45 and CF2/yaw360, verifies all
logged states are finite, and writes `results\gui_smoke_test.json`. It does not
open or command any physical hardware.

The native viewer was additionally lifecycle-tested on Windows with X2/hover:
it opened, synchronized the neural plant for 400 real-time-paced steps, and
closed cleanly. The 0.2 s simulation interval required approximately 0.218 s
of wall time during that validation.
